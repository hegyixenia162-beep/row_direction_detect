# HSV + Hough 运行问题与解决记录

## 1. 项目上下文确认

运行前先读取了同项目相关任务。确认输入为 RGB 原始航片，不存在飞行高度、GSD、地理参考和正射拼接图；最终要求是每个物理种植行一条有限中心线段，而不是只输出全局角度或 Hough 无限直线。因此，本实现没有引入无法获得的元数据，并将端点定义为图内植被证据支持范围的两端。

## 2. 大图计算量

### 现象

测试图尺寸为 `5472×3648` 或 `6144×4096`，单张约 20–25 MP。直接在原图上做连通域、Canny、Hough 和旋转投影会增加运行时间及内存占用。

### 解决

把最长边缩放到 1800 px 的工作尺度完成分割和几何检测，再把掩膜和线段坐标映射回原图。这样保留了整幅图的行排列关系，并把七张图首轮批处理时间控制在约 21 s。输出 JSON 明确记录 `work_scale`，便于复现坐标变换。

## 3. 控制台中文乱码

### 现象

PowerShell 捕获的 Python 标准输出显示为乱码，但进程退出码为 0，结果文件与 UTF-8 JSON 内容正常。

### 原因与处理

这是当前终端捕获编码与 Python 输出编码不一致，不是算法失败。运行状态以退出码、`run_summary.json` 和生成文件为准；文档与 JSON 均显式使用 UTF-8。若需要正常查看控制台中文，可在运行前设置 `PYTHONUTF8=1`，或在 PowerShell 中把输出编码设为 UTF-8。

## 4. Hough 不能直接作为最终线段

### 现象

概率 Hough 会在同一棉行的叶缘、地膜边缘和局部植株排列上产生多条候选线；若直接绘制，会出现一行多线，且线段端点由局部边缘随机决定。

### 解决

Hough 仅用于主方向估计。候选角先做二倍角圆统计，再按主角度容差聚类。每条实际行的位置改由旋正掩膜的法向密度峰确定，每个峰仅建立一个走廊；走廊内按纵向分箱提取中位代表点并稳健拟合中心线。最终端点取代表点沿行方向的 2% 和 98% 分位数，因此是有限线段并具有两个明确端点。

## 5. 自相关行距的谐波歧义

### 现象

首轮结果全部七张图均成功，但对 `1787026853793_29_63.jpg` 的视觉检查发现只输出 4 行。其自相关估计原图像素行距约 1028 px，而图中部分相邻种植行的间距明显更小。原因是强弱行交替时，自相关可能把“隔一行”的强重复周期当成基本周期；原实现又用 `0.55 × 估计行距` 作为投影峰最小间距，因而抑制了相邻弱峰。

### 解决

保留自相关结果作为尺度与质量参考，但把峰值抑制距离改为 `0.22 × 估计行距`。该策略优先召回相邻弱行，再用代表点数量、纵向跨度、角度偏差和最终线段长度过滤短杂草斑。修改后重新运行并再次进行视觉检查。

### 复测结果

二次批处理七张图全部成功，检测行数依次为 18、28、6、6、6、6、5；总运行时间约 25 s。问题样本 `1787026853793_29_63.jpg` 从 4 行提升到 6 行。复查其掩膜后，白色区域主要覆盖绿色植株，灰白地膜和黄褐土壤受到较好抑制；最终图每个候选行均为单条橙色中心线，且两端具有独立圆形端点。该结果是算法运行与视觉合理性检查，不是精度结论；在没有人工逐行真值的情况下，不能把“输出行数”解释为召回率或准确率。

## 6. 方法层面的未解决风险

HSV 掩膜只代表绿色植被，不会区分棉花与杂草。当前样本行结构强、裸土占主导时，长程平行性可以抑制很多杂草，但高密度行间杂草仍可能形成假行。单一全局 Hough 方向也不适用于一张图内存在多个地块方向或强透视的情况。这些属于该零训练基线的能力边界，不能通过继续微调固定阈值彻底解决；后续应在冻结标注集上量化漏行率和假行率，再决定是否升级为局部分块方向场或棉花/杂草语义分割模型。
